# Launch Hazırlığı Planı

LobbyForge'u yayına hazırlamak için 5 iş paketi. Her paketten sonra testler koşulacak.

## Paket 1 — `registrationMode` varsayılanını `open` → `invite_only` (hardening)

**Kaynak değişiklikleri (3 dosya):**
- `packages/db/src/schema.ts:259` — `.default('open')` → `.default('invite_only')`
- `packages/db/src/queries/instanceSettings.ts:70` — `getEffectiveInstanceAccessSettings` fallback'inde `registrationMode: 'open'` → `'invite_only'`
- `apps/web/app/setup/SetupWizard.tsx:73` — initial form state `registrationMode: 'open'` → `'invite_only'`

**Yeni migration (0008 düzenlenmeyecek — zaten deploy edilmiş DB'leri bozar):**
- `pnpm -F @lobbyforge/db db:generate` ile `0017_*.sql` üretilip `ALTER COLUMN ... SET DEFAULT 'invite_only'` içermesi sağlanacak. Sadece varsayılan değişecek; mevcut satırlara `UPDATE` yapılmayacak (kullanıcı kararı).
- `meta/_journal.json`'a idx 17 olarak eklenecek, snapshot güncellenecek.

**Test güncellemeleri:**
- `packages/db/src/__tests__/schema.test.ts:34` — `expect(...default).toBe('open')` → `'invite_only'`
- `apps/web/lib/__tests__/instance-access.test.ts:20` — factory baseline `registrationMode: 'open'` → `'invite_only'` olarak gözden geçirilecek (mevcut `'open'` branch coverage test'i korunacak).

**Davranış notu:** `lobby/page.tsx:417`'deki auto-join (`=== 'open'`) artık tetiklenmeyecek; bu hardening için istenen davranış, kod değişikliği gerekmez.

- `infra/docker/docker-compose.dev.yml` mevcut ve sağlam; `infra/docker/.env.example` de iyi durumda. Kök `.env` ile near-duplicate ama `.gitignore` `.env`'i zaten yok saydığı için bu pasif bırakılacak (silmeye gerek yok).

## Paket 3 — Kök `README.md` yazımı

Yok olan kök `README.md` oluşturulacak. İçerik (STRATEGY.md'deki konumlandırma + mevcut gerçekleri yansıtarak):

- **Rakip haritası / niche** (voice-first + plugin SDK + self-host üçlüsü) — kısa
- **Özellikler:** ses odaları (LiveKit), plugin SDK + Hushle/Quiz oyunları, misafir erişim, Calm Future design, Doctor health/capacity, self-host update sistemi, i18n (EN/TR)

- **Workspace haritası** (apps/packages/plugins) + docs/CONTRIBUTING.md linki
- **Lisans:** AGPL-3.0
- Badge'ler (CI status, Node version, pnpm, license)

Ayrıca **stale README'ler güncellenecek:**
- `apps/web/README.md` — "Planned home" → gerçek açıklama (Next.js App Router uygulaması, lobby, admin, API routes)

## Paket 4 — Repo temizliği

- **Gereksiz arşivler silinecek:** `docs/docs.zip`, `projectdetails.zip` (içerikleri zaten klasör olarak mevcut)
- **`design_stitch_backup/`** — `design_stitch/`'in yedeği; README'de kaynak olarak anılıyor. Silinecek (backup amaçlı, gereksiz dağıtım yükü).
- **Sürüm hizalama:** root `0.0.0` → `0.2.0` (en gelişmiş workspaces web/hushle ile aynı seviyeye). Bu bir başlangıç noktası; her workspace ayrı `package.json`'a sahip olduğu için sadece root hizalanacak, workspace'ler dokunulmayacak (karışıklık riski).

## Paket 5 — Git init + ilk commit

`.git` bozuk/boş. Sıfırdan başlatılacak:
- `.gitignore` zaten iyi durumda (node_modules, .env, .next, dist, .pnpm-store hepsi yok sayılıyor).
- `git init` → branch `main` → `git add -A` → `.env`'in eklenmediğini `git status` ile teyit → anlamlı bir ilk commit mesajı.
- Commit, kullanıcının isteği dışında push yapılmayacak (sadece yerel repo).

## Doğrulama (her paketten sonra + son)
- `pnpm verify` (typecheck + lint + test) — tüm workspace'lerde yeşil olmalı
- `pnpm -F @lobbyforge/web build` — build yeşil
- Migration test'i: yeni `0017` migration'ın journal'da doğru idx'te kayıtlı olduğunun teyidi

## Riskler / notlar
- Migration DB'ye **uygulanmayacak** (sadece dosya üretilip journal'a eklenecek); canlı DB yok. Üretimde `db:migrate` çalıştığında devreye girer.
- `.env` commit edilip edilmediği geçmişte doğrulanamıyor (git bozuk); yeni init ile `.gitignore` garanti altında.
- Sürüm hizalamada workspace'ler dokunulmuyor — sadece root `0.0.0` → `0.2.0`.
